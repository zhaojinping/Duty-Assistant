# trend 判定算法口径收敛提案（草案）

> 卡：#28 ①（M3 设计包）。主设 §12 待定项之一，配套《DSL 缺口清单》GAP-H6（主变「与上次对比」人工列）。
> 依据：`docs/design.md` §5.1（历史契约）、§7.2/§7.3（`trend.source` 文法）、§12（待定项）；`docs/dsl-gap-list.md` §4/GAP-H6、§7 性能项；`src/records_kit/engine/trend.py`（M1 现行默认口径）。
> 状态：**草案**，待总控拍板后并入主设 §7.3 与声明侧。

## 1. 现行实现（可复核，M1 标注为「默认口径待拍板」）

| 环节 | 现行口径 |
|---|---|
| 取值 | `trend.source = agg(field_path)`：每行历史行取一点 + 当前记录一点 |
| 窗口 | 取末尾 `window` 点；不足 → `insufficient_history`（level=info，evidence 注明 `n/window`） |
| 基准 | 窗口内**最早值**（首值） |
| 口径与阈值 | **相对降幅**：`(首值 − 末值) / |首值| ≥ drop_warn` → `dropping`（level=warn），否则 `stable` |
| 缺值 | 当前记录取不到值 → 不输出结论；历史行取不到值 → 跳过该行并计入 evidence（§5.1 旧数据适配） |
| 零基准 | 首值为 0 → `insufficient_history`（相对降幅不可算） |

## 2. 待收敛三项（§12 原文）

`drop_warn` 口径（绝对差值 / 相对比）、比较基准（窗口首值 / 上一值 / 均值）、`stable`/`dropping` 阈值。

## 3. 提案

### 3.1 `drop_warn` 口径 = **相对比**（保留），零基准另立绝对差值参数

- 相对比与量纲无关：电压（V）、电流（A）、温度（℃）可用同一阈值语义，声明侧只写百分比。
- **零基准**（首值 = 0）相对降幅无定义：现行直接 `insufficient_history` 是保守做法，保留为缺省；
- 建议增可选参数 `drop_abs`（绝对差值），仅当**首值为 0 或缺失**时启用该口径判定；`drop_warn` 与 `drop_abs` **同时声明 → 声明加载报错**（避免双重触发口径歧义）。

### 3.2 比较基准 = **窗口首值**（保留）

| 候选 | 取舍理由 |
|---|---|
| **窗口首值**（建议） | 判的是「整段趋势性下滑」，对单点抖动不敏感；现行 evidence 已按 `首值 → 末值` 出文，改动最小 |
| 上一值 | 对单点误录极敏感（一次错录即误报）；且与「与上次对比」人工列（GAP-H6）职责重叠 |
| 均值 | 需额外定义窗口对齐与缺值口径，收益不明显，复杂度换不来判定质量 |

结论：**基准 = 窗口首值**，并把该口径写进主设 §7.3 trend 注（定稿后仅需把 `trend.py` 的「待拍板」注释改为「已定」）。

### 3.3 阈值 = 声明数据（数值缺口），但判定形式收敛为单一形态

- `dropping ⇔ drop ≥ drop_warn`（`≥` 含等于，符号口径定死）；
- 阈值数值属**现场口径**（各 metric 各自定值），本文不给业务数值；
- 判定结果文案、level 归属（`dropping`=warn / `stable`=info）与 `insufficient_history`=info 不变。

### 3.4 必修项：**分组序列**（现行实现缺口）

- 《DSL 缺口清单》§4 把主变 `transformer_id` 同时列为 `dedupe_key` 与 **trend 分组键**，但现行 `evaluate_trend` **不按任何键分组**——多台主变的历史行会串成一条序列，产出**假趋势**（跨设备比较）。
- 建议：`[[trend]]` 增可选 `group = "<字段>"`：
  - 声明 `group` → 只取**同键值**的历史行 + 当前记录（键值取自当前记录 payload）；
  - 缺省不分组（保持现行行为，向后兼容）；
  - 分组键须为顶层字段且非条目容器；条目字段不支持（另案）。
- 声明侧随之补：主变声明 `group = "transformer_id"`；蓄电池/其余类型按序列语义逐类确认（同站同类型单序列时可不写）。

### 3.5 与人工对比列（GAP-H6）的双源口径

- 核心 `trend` = 机读结论；人工「与上次对比」列 = 人工观测记录，**两者互不覆盖**；
- 冲突时**以核心结论为准**，人工列仅在报告层展示（建议；口径需总控确认）。

## 4. 边界例（实现须逐例落为测试）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 窗口不足（3/6） | `insufficient_history`（level=info，evidence `3/6`） |
| 2 | 当前记录 source 取不到值 | `insufficient_history`，不输出趋势结论 |
| 3 | 首值 = 0 且未声明 `drop_abs` | `insufficient_history`（不可算） |
| 4 | 首值 = 0 且声明 `drop_abs = <数值>` | 按绝对差值判定（`≥` 为 dropping） |
| 5 | 降幅恰等于 `drop_warn` | `dropping`（`≥` 含等于） |
| 6 | 历史行 source 取不到值 | 该行跳过，evidence 计入「跳过 N 行」 |
| 7 | `group = "transformer_id"`，台账含两台主变 | 序列隔离：A 台趋势不消费 B 台历史行 |
| 8 | 未声明 `group` | 保持现行（全部历史行合一序列），行为与 M1 一致 |
| 9 | 同时声明 `drop_warn` 与 `drop_abs` | 声明加载报错（口径互斥） |
